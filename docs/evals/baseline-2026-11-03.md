# The first automated eval of /ask (3 Nov 2026)

A page for someone new to this repo: what was built on Tuesday of week 5, why, and what it showed.

## The project in three lines

`ai-labs` is a .NET 10 solution for learning to build with LLMs. Its RAG service, `AiLab.Rag`, answers questions about a small set of docs (4 Markdown files in `data/corpus/`) through **`POST /ask`**:

1. find the 5 closest chunks in Postgres (pgvector)
2. stop early if nothing is close (the "gate")
3. send the chunks to a model with numbered sources
4. check that the answer only cites sources that were sent

Example: *"What is the current internal billing contract version?"* → *"The current internal billing contract version is `2026-03-18` [1]."*

## The question of the day

Unit tests (`AiLab.Rag.Tests`) prove the code works, using a fake model. They can't say whether the **real** model gives good answers. Week 4 answered that by hand: 20 questions, every reply read and labelled. On Monday that became a fixed set of 30 questions with gold answers ([ask-set-v1](ask-set-v1.md)) and a plan for measuring them ([eval-plan](eval-plan.md)).

Tuesday's goal: **score `/ask` on all 30 questions automatically, from `dotnet test`, and record a first baseline** to compare every later change against.

## What was built

A new test project, **`AiLab.Evals`**, using Microsoft's evaluation library for .NET (`Microsoft.Extensions.AI.Evaluation`, "MEAI"). Details: [meai-evals.md](meai-evals.md).

- **The 30 questions as data:** `docs/evals/ask-set-v1.json`. Offline tests check it against the Markdown set and the corpus. They found three wrong gold line numbers, now fixed.
- **One test row per question, 3 runs each**, through the real `/ask`: the real Postgres, embeddings and prompt.
- **Five scores per run:**

  | Score | Who scores it | Question it answers |
  |---|---|---|
  | Groundedness (1–5) | a judge model | Is the answer supported by the chunks that were sent? |
  | Relevance (1–5) | a judge model | Does the answer address the question? |
  | Retrieval (1–5) | a judge model | Are the chunks relevant to the question? |
  | Recall@5 (0–1) | plain code | Was the chunk holding the gold answer among the 5 sent? |
  | Ask outcome | plain code | Status, gate, tokens and time of the `/ask` call |

- **The judge is Claude Haiku 5.5.** A small wrapper (`HaikuJudgeOptionsClient`) removes the sampling settings Haiku refuses and gives it room to think.
- **Every model call is cached on disk.** Running the same evaluation again costs nothing and takes seconds.
- **Plain `dotnet test` stays offline:** the eval tests skip unless `AILAB_EVAL=1` is set.

## What came out

| | Haiku answers | llama3.2 answers (local) |
|---|---|---|
| Groundedness (avg) | **4.93**, no run below 4 | **4.15**, 10 runs below 4 |
| Relevance (avg) | 4.19 | 3.72 |
| Retrieval (avg) | 3.83 | 3.83 (same chunks) |
| Recall@5 | 0.96: every English question's answer was sent; the French one missed | same |
| Cost, time | $0.19, 6 min 37 s | $0.06 (judges only), 45 min (one stuck call) |
| Same run again from the cache | **$0.00, 3 seconds**, identical scores | |

What the numbers say:

1. **Retrieval is not the problem on this corpus.** For all 24 English questions that have an answer, a chunk holding the gold line was sent, usually at rank 1 (MRR 0.77). Only the French question misses: the embeddings are English-only.
2. **Haiku answers well.** Its answers are supported by the sources. On all 12 runs of questions that aren't in the docs, it said so, though `/ask`'s status only says `abstained` on 3 of them (it cites what the docs do say).
3. **The judge scores are signals, not verdicts.**
   - Groundedness tells the two models apart and caught llama3.2's invented numbers ("60 minutes", "5 attempts per 5 minutes" for password reset).
   - It missed general-knowledge answers (llama3.2's definition of "multi-tenancy" scored 4).
   - It lowers scores for missing details, not only for unsupported ones.
   - Relevance gives 3 out of 5 to correct answers like "the docs don't give a default value", so it can't decide pass or fail on those questions.
4. **The judge isn't trusted yet.** Checked against the 40 hand-labelled week 4 answers, it found 5 of the 7 known invented answers and raised 3 false alarms: precision 0.63, recall 0.71. The eval plan asks for about 0.8 on both, so faithfulness stays scored by hand for now.

Full numbers, per category and per question: [experiments.md, section 15](../../experiments.md).

## Why it matters

Before Tuesday, checking `/ask` after a change meant reading 30 answers by hand. Now one command runs the set, scores it and stores the results. A cached re-run is free, so the scores can be compared after every prompt, model or chunking change. The baseline is the reference point for those comparisons. It also showed which scores can be trusted for which questions, and which can't yet.

## Run it yourself

Needs Ollama, Postgres (`colima start`, `docker compose up -d`), the corpus ingested, and an Anthropic key in user-secrets for the Haiku judge.

```bash
# free check of the wiring (llama3.2 answers and judges, one question)
AILAB_EVAL=1 AILAB_EVAL_ANSWERS=llama AILAB_EVAL_JUDGE=llama AILAB_EVAL_RUNS=1 dotnet test AiLab.Evals --filter 'DisplayName~A3'

# the Haiku baseline (~$0.19; free when cached)
AILAB_EVAL=1 dotnet test AiLab.Evals --filter AskSetEvalTests

# a markdown summary, and the HTML report
AILAB_EVAL_SUMMARY=baseline-2026-11-03-haiku dotnet test AiLab.Evals --filter Write_summary
dotnet aieval report --path eval-runs/meai --output eval-runs/meai/report.html
```

## Known limits

- **Self-grading:** Haiku judges Haiku's answers.
- The judges skip any run `/ask` marked `abstained`, including answers that are only partly an abstention.
- **One judge call hung** for about 35 minutes before the SDK gave up. The judge now has a 60-second timeout per attempt.
- Cache keys depend on the library version; an upgrade means paying for the calls again.
