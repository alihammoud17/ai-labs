- **Scope:** all code in `AiLab.Core`, `AiLab.Api`, `AiLab.Api.Tests` and `AiLab.Console`. The repository's first commit is from this week, so everything is in scope.

Severity:
- **high:** real money or data at risk in production as the code stands.
- **medium:** a wrong result, a misleading error or an untested failure path that matters before production.

## Checked, no finding

- **Cancellation:**
  - The request token reaches every model call.
  - A cancellation we asked for (client gone, request timeout) is left to ASP.NET Core.
  - An SDK timeout (a cancellation we didn't ask for) becomes a 502.
  - The eval passes its token to every file write.
- **Secrets:** the API key is read only from configuration, and user-secrets load only in Development. No key is in code, appsettings, tests or the README. The tests run in the `Testing` environment with no key.
- **Exception details:** `IncludeDetailedErrors = false` is explicit, and test 8 proves no exception text reaches the model. Error bodies carry no stack traces or model text (the 422 reason goes to the log only).
- **Retries:** exactly one layer per provider (Polly for Ollama, the SDK for Anthropic). The tool loop is capped (`MaxToolIterations` 3), and there is at most one repair.
- **Failure-table rows marked handled** (10, 13, 14, 15, 18, 20) behave as the table says, and each has a test, except that row 18's `tool_failed` 502 path is only reachable with several calls per step.

## Summary

The defensive-UX work holds up. The grounding check, the error codes, the repair and the 422 path are correct and tested, and the code builds clean.

The serious gaps are the ones the failure table already lists as open and that this week didn't target:
- no authentication or rate limit,
- no input size limit,
- an unbounded tool result.

Together they mean an anonymous caller can make the API spend real money at will.

The most important new issues:
- **M1:** every Anthropic 4xx is reported as "provider unavailable".
- **M2:** `ToolMode.None` is ignored by OllamaSharp, so a repair can run a second tool loop.
- **M3:** ticket text can manufacture a `grounded` status.

The test suite covers the happy and unhappy model replies well, but not provider and timeout failures, or the two projects outside the API.

## Fix first

1. **H1, auth and rate limiting:** the only thing standing between the endpoint and unlimited spend.
2. **H2, input size limits and component validation:** cheap to add, removes both a cost multiplier and Ollama's silent prompt truncation.
3. **M1, map Anthropic 4xx errors correctly:** a bad key or retired model currently looks like an outage, which is the hardest kind of failure to diagnose in production.
